# Windows 灵动岛 UI/UX v1.0 复刻与三处视觉问题修复

本轮基于 `main / b19121a` 及开始时已有的未提交动效恢复修改继续工作。原始 UI 规范、检验阅读设计输入、历史证据和 Rust/TypeScript/React 性能优化保留。当前证据使用 `evidence/uiux-refinement-20261013/`；最终汇总为该目录的 `RESULTS.json`。本轮没有提交或推送。

## 三处问题

| 用户截图 | 原因与处理 | 当前验证 |
|---|---|---|
| 900×590 灰色背景框 | 与原生 QA 的无标题合成底板尺寸及 `#dbe5e8` 完全一致；应用原生画布是 704×622，页面 html/body/root 为透明。本轮底板在 `finally` 关闭，正常启动只显示岛 | 透明画布回归；测试后窗口清单；正常启动检查 |
| 默认态两侧接近白色的竖线 | Tao 在 `decorations=false` 时仍保留原生 caption/edge 标志。清除标志、禁止 DWM 额外边框后，实际像素仍有亮边：旧非客户区缓存没有刷新。首次区域安装并显示 HWND 后做一次 `RedrawWindow`，清除缓存 | 新 EXE 实际暗色底板亮边像素 **0**；透明 fringe 保留；首次失败及单变量探针保留 |
| 默认 hover 的灰白高亮框 | 通用 `.ci-host button:hover:not(:disabled)` 比原覆盖规则更具体，实际填充为 `#2C2C2E`；还显示横线并把 S0 放大到 130.2×33.6 | S0 保持 **124×32**，按钮背景透明、仅手形光标、无横线；键盘焦点环保留 |

S0 hover 以用户本次明确要求为准，覆盖规范的通用 Peek 描述。有活动的 Compact 仍按规范在 120ms 后进行 1.05 微扩；检验 alert 沿用独立设计。点击反馈、键盘、读取预算及隐私清理保留。

原生修改清除 `WS_CAPTION/WS_THICKFRAME` 与系统 edge/APPWINDOW，使用 TOOLWINDOW/NOACTIVATE，并设置 DWM 非客户区策略、无系统圆角及无额外边框。首次 `RedrawWindow` 在真实轮廓准备后执行；正常动效继续只做有限轮廓交接，HWND 不变。对照 [微软 DWM 属性文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。

## 验证与可复现性

- TypeScript 单元 **238/238**；Rust Release **15/15**；Clippy `-D warnings`；前端、桌面 Release 构建及来源包边界检查通过。
- 完整独立 Chrome 回归 **105/105**，0 skipped、0 unexpected、0 flaky。临时测试配置只复用已核实的旧合成来源 17322；默认项目配置未改为自动复用未知服务。
- 新原生 QA 通过 `optimization-qa.ps1 -SourcePort 17323` 创建独立来源、临时 profile 和显式 9223，按 PID/启动时间/EXE/hash 核实所有权。最终 EXE/hash、屏幕样本数、rAF、进程树及清理记录在 `RESULTS.json` 中。
- 保留稳定 HWND、单在途 region、最终 paint 交接、授权即时移除、阅读生命周期及 typed source 协议；没有临床确认、处置、派单、财务、处方或治疗写入。

本机 Windows 动画开关仍为关闭。应用完整动效选择只覆盖本应用；减弱模式即时切换回无位移/模糊/缩放，未更改 Windows。整应用内存含 WebView2，指标及口径保留原始文件；短样本不代表 §11 的完整 CPU/GPU/内存设备验收。

## 本轮保留的失败

初始 QA 原生 hover 复现为灰底、横线和放大；早期测试因旧 17322 服务占用或沙箱连接受限未运行。新增 `CustomEase` 最初直接传完整 CSS 字符串导致加载失败，改为原四个坐标后通过；Compact 与 Minimal 新夹具的初始化/自动预览设置错误已修正。旧 EXE 被占用且 OS 拒绝结束，用户退出后构建通过。

清除边框标志的首个 EXE 实际仍有 98/108 个亮像素；关闭 blur 的单变量探针无效，完整刷新清为 0，随后写入首次显示流程并在新 EXE 复核。后执行的 alpha 探针发生在缓存已清除之后，不能归因于 alpha 修改，生产代码未采用该修改。所有原始日志/探针记录保留；不把旧 EXE、窗口样式检查或 rAF 冒充最终屏幕结果。

电脑/Chrome 插件的直接窗口或页面查看曾被工具权限策略拒绝。本轮屏幕验证使用新建、所有权核实的专用 QA 会话及合成底板，不访问用户浏览器 profile；没有将未执行的插件交互检查写为通过。
