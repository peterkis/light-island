# UI/UX v1.0 动效恢复与生效诊断（2026-10-13）

本轮起点：`main / b19121a38ee8b4e3bb815b4885f6d44d9d4259a3`，开始时工作区干净。用户要求恢复规范中的动效，而非回滚临床阅读器或性能优化。原始 `Windows 灵动岛 UI UX 设计规范 v1.0.md` 与两份检验阅读设计输入保持不变。当前证据使用 `evidence/motion-restore-20261013/`；旧版本结果不计入本轮验收。

## 已确认原因

1. 本机只读调用 `SPI_GETCLIENTAREAANIMATION (0x1042)` 成功，返回 **FALSE**。当前原生岛使用 `应用 reduced || 浏览器 prefers-reduced-motion || !Windows animationsEnabled`，因此应用内 reduced=false 仍不能恢复动效；设置文案没有显示这个最终原因。前两次性能优化报告也明确只有原生减少动态路径验收，不应把它们理解为普通弹簧被优化移除。
2. CSS 另有全局 `@media(prefers-reduced-motion:reduce)` 禁用规则。只改 JavaScript 会留下“两套开关”：即使外壳开始动，CSS 的报告焚毁、计时结束等效果仍可能静止。
3. 通用内容入场、退场把 `scale` 固定为 1，与第9.4节 `.96→1` 不符。完整模式恢复该参数，专门检验阅读器保留自身不可变设计约束。
4. 数字仅更新文本，没有第9.5节要求的变化位翻页。本轮补齐按位、有限的200ms过渡和计数徽标出现弹簧，不引入空闲循环。

## 生效模式与安全边界

- 新安装默认“跟随系统”；系统或浏览器要求减少动态时仍使用150ms淡入、直接尺寸切换，不绕过用户偏好。
- 用户明确选择“完整动效（仅此应用）”才覆盖系统减少动态信号。Windows 全局设置不改变；已有应用“减少动态”开关为最高优先级，随时可返回减少模式。
- 工作台与岛内右键设置均可选择模式并显示原因。原生只持久化一个 `system/full/reduced` 枚举，放在应用配置文件 `motion-preference.json`。不保存患者、来源对象、报告或阅读历史；临床 WebView 仍使用原有临时隐私 profile。
- 权限、锁屏、阅读预算、版本失效、临床只读、报告清除等继续优先于装饰动效。没有新增临床写接口或系统输入监视。
