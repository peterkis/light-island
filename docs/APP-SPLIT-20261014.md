# 灵动岛与原型工作台：独立程序

本次拆分保留现有 UI/UX v1.0、动效和原生窗口修复。两份 EXE 共享源代码中的渲染组件、协议与合成夹具；运行时状态、资源包、WebView 会话和生命周期独立。

## 使用与构建

- `npm run desktop:build`：构建两个程序，复制到 `dist/desktop/`。
- `npm run desktop:build:island` / `npm run desktop:build:workbench`：独立构建。
- `npm run desktop:dev:island` / `npm run desktop:dev:workbench`：独立开发。
- `scripts/start-prototype.ps1` 默认打开两个程序；`-IslandOnly`、`-WorkbenchOnly` 分别启动；`-Legacy` 选择旧版实验。`-SourcePort 17323` 可显式选择另一个本地端口，默认仍为 17322。
- 正常发布只需要两个 EXE 和 Windows WebView2。工作台内置 Rust/Tokio/Axum 模拟服务，不依赖 Node 进程。
- 灵动岛 `--studio` 兼容启动另一个工作台进程。重复启动灵动岛打开自己的消息视图，不创建工作台。

灵动岛保留标识 `local.samewave.island.prototype`。工作台使用 `local.samewave.workbench.prototype`；显式旧版实验使用其独立 `legacy` 标识，避免两个模拟端口互相替代。

## 状态与接口

灵动岛拥有计时截止时间、暂停剩余时间、展示偏好、静音、撤销、展开和阅读会话。来源快照只包含来源设置及活动对象，不含个人计时或展示偏好。只保留既有动效枚举持久化，不新增运行状态落盘。

两个程序分别在自身应用标识对应的配置目录保存 `system/full/reduced` 动效枚举。工作台通过自己的原生接口读写，不依赖退出时清除的 WebView 存储，也不会修改岛的偏好。

工作台默认选择“工作台独立预览”。预览与桌面拥有不同的模拟源状态；选择桌面连接后，场景按钮及实验命令只发送到该目标。普通预览点击、阅读、设置和计时始终只影响预览。个人计时不受模拟重要事件、来源重置或连接重建影响。

默认来源 `ws://127.0.0.1:17322/events`；旧版实验使用 17321。临床握手为协议 v2，包含来源会话标识、客户端角色和连接标识。只读请求与私有响应携带会话信息；来源重启后旧票据、请求和迟到回复失效。连接兼容并完成订阅后才标记在线。

原生工作台预览只在自身服务确认监听后连接，并将握手会话固定为原生状态中的会话标识。绑定失败时保持离线并按有界退避重新检查；不会接入占用该端口的其他 v2 服务。

来源通道接受同步、刷新、对象入口、来源读取、报告读取和相关实验反馈。模拟配置与重置由工作台自身原生接口执行。明确的实验动作单独传输，不能授予来源权限，也不能形成临床接收或处置。

工作台退出即停止监听。灵动岛保留离线摘要，立即清除报告、详情和待处理读取，个人工具继续运行。重连重新获取快照，不更新原始同步时间，不重播旧预览。新来源会话清除旧临床镜像，不清除个人工具。

工作台控制源容量 20 项、连接 8 个、有界发送队列 64 项、私有/实验相关请求 64 项。命令最大 32 KiB，来源帧最大 256 KiB；慢消费者明确断开后重新读取快照。内存队列不提供持久或无损交付。

## 原生与资源边界

只读来源窗口归灵动岛；工作台预览使用覆盖层。工作台不包含原生岛的 HRGN、阴影、焦点、捕获保护或阅读时钟命令。

岛的独立资源包不包含工作台组件、场景目录和模拟实现。`bundle:check` 同时检查来源阅读包和两套应用边界。原生几何、稳定 HWND、SVG 单一所有权和有限轮廓交接保持现有实现。

## 验证与证据

`npm run test:protocol` 对照 95 个确定性来源案例。Rust 引擎读取同一合成报告 JSON，并在测试中比较同一来源契约；浏览器回归包含两个视图的独立计时与目标分发。

新证据位于 `evidence/app-split-20261013/`，最终状态以该目录的 `RESULTS.json` 为准；早期失败保留。原生 QA 只启动新的、受归属检查保护的程序：岛 `--qa-cdp` 9223，工作台 `--qa-cdp` 9224，`--qa-control` 才开放 HTTP 实验适配器。正常启动均关闭。端口占用不停止其他进程。

原生屏幕连续性与 rAF 回调采样分别报告；内存统计包含各自完整 WebView2 进程树。Windows/DPI/设备条件未实测时继续标记 NOT_RUN。

所有来源仍为合成数据；角色模拟和本地控制不是生产授权机制。未连接真实医院系统，未增加临床业务写入。
