## 分开确认两条故障链
### 关闭触发第二次退场
点击展开视图右侧关闭按钮时，业务模式先变为 compact，但鼠标仍处于旧的大外壳内。原逻辑以 hovered=true 选择 170×37；随着外壳收缩，鼠标真正离开，80ms 复核更新 hovered=false，再次取消并启动同一 compact 退场时间线。
新增 `tests/click-transition.spec.ts` 后，修复前 GSAP、CSS 两条路径均失败：一次关闭记录到两次 compact motion-start。不能把它当作普通的弹簧回弹。

### 原生窗口收紧产生空白帧
在真实 Windows WebView2 上，通过本应用按钮的 DOM 激活执行展开、关闭，并在自建合成背景上捕获屏幕。该采样不是物理鼠标点击验收。
`evidence/click-fix-20260930/before-render/frame-0049.png` 有待机外壳；`frame-0050.png` 外壳完全消失；`frame-0051.png` 又恢复。相应窗口矩形在这一段由 995×60 变成 179×41。
因此，上一轮只固定 compact idle/hover 的承载范围还不够：点击和关闭仍会使 HWND/WebView2 的坐标及绘制缓存发生重布局。这里只把观察到的“窗口调整与空帧”写为事实，不宣称已跟踪 DWM 内部每一步，也没有将 GSAP 定性为无限循环。

## 本轮修补
1. `renderLimits/renderCanvas` 从所有现有横向形态、两条缓动的最大超调、中断反转边界、DPI 和抗锯齿余量推导一个有界薄型画布。点击、关闭、悬停不再调整 HWND 原点或尺寸；启动及显示环境改变仍可重新计算。
2. 画布不是命中矩形。所有形变都沿当前 silhouette 更新 HRGN；不再在通知 begin 阶段把全矩形当作临时点击目标。
3. 每个原生绘制交接先保留“上一帧和下一帧轮廓的并集”，收到区域更新响应后才呈现下一帧。过渡完成并经过有限绘制机会后恢复最终轮廓。保留原有 2 个物理像素抗锯齿余量和 HRGN 所有权规则。
4. 区域更新使用一个在途请求和最新待呈现几何；同一帧宽、高写入用 microtask 合并，不额外等待一个 rAF，避免将实际更新频率降到隔帧一次。静止时没有循环或轮询。
5. compact 微悬停只在内容形态已经收敛后响应。关闭过程中的真实 leave 仍更新业务 hovered，但不再取消、重播正在退出的内容。若收回后鼠标仍在中央，只执行一次不换内容的正常微扩。
6. CSS 路径用临时、不可见且不接收指针的测量元素执行尺寸插值；实际外壳与 GSAP 共用原生确认后的呈现路径。结束、取消和卸载均移除测量元素。
7. 保留现有 epoch、帧序号、取消与过期提交保护，增加收敛入口防重入。保留主题、隐私、优先级、确认回执、专注模式及 120ms peek。

## 对旧约定的必要修正
原先“通知结束后 HWND 收紧到当前外壳”和“只有 compact 共用小画布”现在是历史策略。本轮将坐标稳定性扩大到所有现有横向消息形态，但没有扩大实际可点击区域为画布矩形，没有使用全屏透明窗口，也没有改动视觉尺寸或服务器架构。

## 瞬时关闭的悬停意图
原生真实点击补充检查发现：减少动态模式关闭时，命中区域可在 WebView2 发出 leave 前立即缩小，鼠标在旧右侧关闭按钮位置而 hovered 仍为 true。最终在右侧关闭动作本身清除宽视图的悬停意图，与 mode=compact 同批更新；不依赖之后一定收到 leave。Esc 的中央悬停行为单独保留，没有新增常驻位置轮询或定时恢复。
最终物理点击回归新增断言：每次右侧关闭后 hovered=false，而不是只验证最终尺寸和 opacity。之前只验证尺寸/epoch 的中间记录被保留为 `pre-final-close-*`，不能替代最终回归。

## 原生数据边界
原生验收期间还修正了动画代理对象携带内部缓存的问题：待提交及已绘制几何只保存 width/height/radius/ear，IPC 轮廓仅传入 width/height/points，不能把 GSAP 代理内部的循环引用带进通信或诊断记录。
